Fixing "topical but not verifying" retrieval

the root cause + the ranked fixes for VerifAI

0root cause

The retriever is a paraphrase bi-encoder + cosine — it scores aboutness (topic), not entailment (does this verify the claim?). Cosine 0.45–0.70 = "same subject", which is exactly topical-not-verifying.
⚠️ fix = add a stage that scores VERIFICATION, not topic.

1NLI / stance reranker + entailment gate (THE fix)

Score (claim, passage) → entail / refute / neutral; keep only entail/refute. Your reranker.py slot already exists — relevance entailment. This is the FEVER-style verify step.
gate evidence on entailment, not cosine. no verifying passage → claim-only.

2hybrid retrieval — BM25 + dense (RRF)

Claims hinge on named entities ("Katy Freeway", "Tim Kaine"). Lexical match nails them; dense blurs them. Fuse both for recall.

3better query + finer chunks

Raw claim is a bad query → use extract_claim() (proposition + entities) or HyDE. Chunk to sentences, not 500 chars — verifying facts are one sentence; big chunks dilute.
#4 optional: swap the paraphrase embedder for a retrieval-tuned one (e5 / BGE-m3). That's retrieval infra, not the from-scratch classifier — check your rubric.

!two honest caveats

LIAR ceiling: its claims are PolitiFact-sourced; the real verifying evidence is the fact-checkers' own analysis → using it = contamination. Independent corpora often lack the refuting fact. So scarcity may be structural, not just tuning.
Tiny model: the 6.3M from-scratch classifier may not exploit even perfect evidence the way Claude does end-to-end.
Build #1 (NLI-gated evidence). It converts topical→verifying and is a real contribution to §5.6 even if the number stays flat — "evidence gated on entailment" vs "on topicality".
